## วิธีอ่าน

**ที่มาหลัก** ของแต่ละส่วนมีห้าแบบ:

| ที่มาหลัก | ความหมาย |
|---|---|
| ข้อกำหนด | มีเพราะ FR / NFR / AC / SEC / PRIV / IP ใน backlog กำหนดไว้ |
| กฎ rule.md | มีเพราะกฎใน rule.md บังคับ เช่น ต้องติดป้ายข้อมูลสมมติตาม rule 85 |
| เอกสารออกแบบ | มาจาก `.docs/02-design/` เช่น roles-permissions, user-journey, openapi |
| คำขอเจ้าของ | เจ้าของโครงการขอเพิ่มในเดโม และมีบันทึกพร้อมวันที่ใน prototype.md หรือ design-decisions.md |
| เฉพาะเดโม | ค้นเอกสารแล้วไม่พบฉบับใดที่ขอส่วนนี้ เป็นตัวช่วยของเดโมเอง |

ในช่อง **มาจากเอกสาร** citation ถูกจัดกลุ่มตามความสัมพันธ์:

| คำ | ความหมาย |
|---|---|
| คำขอเจ้าของ | เอกสารบันทึกว่าเจ้าของโครงการขอส่วนนี้ |
| ทำตาม | เดโมทำงานตามที่เอกสารกำหนด โดยทำในหน่วยความจำของเดโม |
| จำลองแทน | เอกสารกำหนดความสามารถนี้ไว้ เดโมใช้ข้อมูลหรือขั้นตอนสมมติแสดงแทน |
| ข้อจำกัด | กฎหรือขอบเขตที่ส่วนนี้ต้องปฏิบัติตาม เช่น ต้องแสดงข้อมูลไม่เพียงพอ หรือห้ามใช้ข้อมูลจริง |
| บันทึกการตัดสินใจ | บันทึกใน design-decisions.md หรือ prototype.md ที่อธิบายว่าทำไมทำแบบนี้ |
| อ้างอิงหน้าตา | แหล่งอ้างอิงด้านภาพ เช่น Claude artboard ที่เจ้าของส่งมา |

README, PRESENTATION, DEMO และ validation ของเดโมเป็นเอกสารที่อธิบายหรือทดสอบเดโม ไม่ใช่ที่มาของส่วนต่าง ๆ จึงไม่นำมาอ้าง

**สถานะในเดโม** มีห้าแบบ: **ทำงานจริงในหน่วยความจำ** คือกดแล้วสถานะเปลี่ยนจริง แต่หายเมื่อรีเฟรช · **ข้อมูล/กระบวนการสมมติ** คือค่าหรือขั้นตอนที่เขียนไว้ล่วงหน้า · **ข้อมูลไม่เพียงพอโดยตั้งใจ** คือส่วนที่ระบบจริงต้องคำนวณ เดโมจึงตอบว่าข้อมูลไม่เพียงพอ · **ตัวช่วยพรีเซนต์** คือคำอธิบายสำหรับผู้นำเสนอ · **ข้อความคงที่**

## ทำเอกสารนี้อย่างไร และควรอัปเดตเมื่อไร

เริ่มจากไล่โค้ดเดโมทีละหน้าเพื่อแยกส่วนที่มองเห็นบนหน้าจอ แล้วค้นเอกสารโครงการทุกฉบับในแผนที่เอกสารของ [CLAUDE.md](../../CLAUDE.md) จากนั้นตรวจซ้ำโดยตั้งใจหาข้อผิด คือเปิดเอกสารที่อ้างทุกครั้งเพื่อยืนยันเลขบรรทัด รหัสข้อ และข้อความ แก้หรือลบ citation ที่ไม่ตรง และตรวจรอบสุดท้ายว่ามีส่วนบนหน้าจอใดตกหล่น การทำเอกสารนี้ไม่ได้ใช้ข้อมูลในโฟลเดอร์ข้อมูลของเจ้าของ หรือเอกสารของอาจารย์ที่ไม่ได้ commit

เมื่อเพิ่มหรือลบส่วนบนหน้าจอ หรือแก้ FR หรือ rule ที่ถูกอ้าง ให้แก้แถวที่เกี่ยวข้องในชุดเอกสารนี้ด้วย ส่วนที่ "มาจาก" คำขอเจ้าของต้องมีบันทึกพร้อมวันที่ใน prototype.md หรือ design-decisions.md ก่อน และห้ามเติมที่มาที่หาเอกสารยืนยันไม่ได้
